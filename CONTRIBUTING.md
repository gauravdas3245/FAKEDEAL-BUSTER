
# Contributing to FakeDeal Buster

Thank you for contributing to FakeDeal Buster!

This project follows a fork-based contribution workflow. The central repository is maintained by the Team Leader.

## Team Workflow

1. Fork the central repository into your own GitHub account.
2. Clone your fork to your computer.
3. Create a separate branch for each task.
4. Make your changes and test them.
5. Commit and push your changes to your fork.
6. Open a Pull Request (PR) to the central repository.
7. The Team Leader reviews the PR and merges approved changes.

## Important Rules

- Do not push directly to the central `main` branch.
- Do not work directly on the `main` branch of your fork.
- Use meaningful branch names, such as `feature/frontend-login` or `fix/api-validation`.
- Write clear commit messages.
- Test your changes before creating a Pull Request.
- Do not upload passwords, API keys, `.env` files, or personal information.
- Do not upload the complete raw dataset to GitHub.
- Coordinate with the team before changing shared APIs, data formats, or project structure.

## Pull Request Guidelines

Every Pull Request should include:

- A clear title describing the change.
- A short explanation of what was changed.
- Relevant screenshots, if applicable.
- Testing details.
- Any known limitations or issues.

## Review and Approval

The Team Leader reviews contributions for correctness, compatibility, and project requirements. Changes are merged into the central `main` branch only after approval.

## Questions

Discuss task-related questions and integration issues with the team before making changes that affect other modules.
